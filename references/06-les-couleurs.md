Chapitre 5 — Les Couleurs

Les couleurs ne servent pas à décorer une interface. Elles servent à communiquer.

⸻

Objectif

Construire un système de couleurs cohérent, accessible et réutilisable.

Une bonne palette de couleurs :

* facilite la lecture ;
* guide l’utilisateur ;
* crée une identité visuelle ;
* améliore l’accessibilité ;
* renforce la hiérarchie.

Le choix des couleurs ne doit jamais être laissé au hasard.

⸻

La couleur est un langage

Chaque couleur transmet une information.

Avant de choisir une couleur, demande-toi :

Que doit comprendre l’utilisateur ?

Une couleur doit toujours avoir une fonction.

Par exemple :

* bleu → action principale ;
* vert → succès ;
* rouge → erreur ;
* orange → avertissement ;
* gris → information secondaire.

Une même couleur doit toujours conserver la même signification.

⸻

Le système de couleurs

Une interface moderne repose généralement sur six familles de couleurs.

1. Couleur primaire

La couleur principale représente la marque.

Elle sert aux :

* boutons principaux ;
* liens importants ;
* éléments actifs ;
* composants sélectionnés.

Une seule couleur primaire suffit dans la majorité des cas.

⸻

2. Couleur secondaire

Elle complète la couleur principale.

Elle est utilisée avec parcimonie pour mettre en valeur des actions secondaires ou des catégories.

Elle ne doit jamais rivaliser avec la couleur primaire.

⸻

3. Couleurs neutres

Les couleurs neutres sont les plus utilisées dans une interface.

Elles servent aux :

* arrière-plans ;
* cartes ;
* bordures ;
* textes ;
* icônes ;
* séparateurs.

Une bonne palette comporte plusieurs niveaux de gris.

Exemple :

50   Fond principal
100  Fond secondaire
200  Bordures légères
300  Bordures
400  Texte désactivé
500  Texte secondaire
700  Texte principal
900  Titres

Les gris structurent l’interface.

Les couleurs d’accent attirent l’attention.

⸻

Les couleurs d’état

Une interface doit posséder des couleurs dédiées aux états du système.

Succès

Vert.

Exemples :

* paiement validé ;
* sauvegarde réussie ;
* compte créé.

⸻

Erreur

Rouge.

Exemples :

* mot de passe incorrect ;
* paiement refusé ;
* suppression impossible.

⸻

Avertissement

Orange.

Exemples :

* espace disque faible ;
* abonnement expirant bientôt ;
* modification importante.

⸻

Information

Bleu clair ou cyan.

Exemples :

* conseils ;
* notifications ;
* nouveautés.

⸻

Une couleur = une signification

Une erreur fréquente consiste à réutiliser la même couleur pour plusieurs usages.

Exemple :

Le rouge sert :

* aux promotions ;
* aux erreurs ;
* aux notifications ;
* aux boutons.

L’utilisateur ne comprend plus le message.

Chaque couleur doit conserver une fonction stable.

⸻

Les contrastes

Une belle palette ne suffit pas.

Elle doit rester lisible.

Le texte doit toujours se détacher clairement de son arrière-plan.

Avant de valider une couleur, vérifie :

* le contraste ;
* la lisibilité ;
* l’accessibilité.

Une interface élégante mais difficile à lire est un échec.

⸻

Les couleurs de fond

Les grands aplats très saturés fatiguent les yeux.

Préfère :

* des gris très clairs ;
* des blancs cassés ;
* des fonds légèrement colorés.

Les couleurs vives sont réservées aux éléments importants.

⸻

Les couleurs d’action

Les boutons principaux utilisent la couleur primaire.

Les boutons secondaires utilisent :

* un contour ;
* un gris ;
* une couleur moins contrastée.

Les boutons destructifs utilisent le rouge.

Cette hiérarchie doit rester constante.

⸻

Les liens

Les liens doivent être immédiatement reconnaissables.

Ils doivent conserver le même style dans toute l’application.

Exemple :

* couleur primaire ;
* soulignement au survol ;
* état visité si nécessaire.

⸻

Les graphiques

Dans les graphiques :

Ne choisis jamais des couleurs uniquement parce qu’elles sont jolies.

Les couleurs doivent rester :

* suffisamment contrastées ;
* faciles à distinguer ;
* cohérentes avec le reste du produit.

Limiter le nombre de couleurs améliore la compréhension.

⸻

Les couleurs et les émotions

Les couleurs influencent la perception.

Sans être des règles absolues, on observe souvent les associations suivantes :

Couleur	Impression fréquente
Bleu	Confiance, stabilité
Vert	Réussite, nature, validation
Rouge	Urgence, erreur, danger
Orange	Attention, énergie
Jaune	Optimisme, prudence
Violet	Créativité, innovation
Noir	Élégance, puissance
Gris	Neutralité

Ces associations varient selon les cultures et le contexte.

⸻

Les erreurs fréquentes

❌ Utiliser trop de couleurs.

❌ Donner plusieurs significations à une même couleur.

❌ Employer des couleurs trop saturées partout.

❌ Utiliser uniquement la couleur pour transmettre une information.

❌ Ignorer les problèmes de contraste.

❌ Changer les couleurs d’une page à l’autre sans logique.

⸻

Les palettes

Une bonne palette contient généralement :

* 1 couleur primaire ;
* 1 couleur secondaire (facultative) ;
* 8 à 12 gris ;
* 1 palette de succès ;
* 1 palette d’erreur ;
* 1 palette d’avertissement ;
* 1 palette d’information.

Chaque palette comprend plusieurs nuances, du plus clair au plus foncé, afin de répondre aux différents besoins de l’interface (fonds, bordures, textes, éléments actifs, etc.).

⸻

Cas pratique

Imaginons une application bancaire.

Une mauvaise approche utiliserait :

* des boutons rouges ;
* des alertes rouges ;
* des promotions rouges ;
* des cartes rouges.

Tout semble urgent.

Une meilleure approche réserverait :

* le bleu pour les actions principales ;
* le vert pour les validations ;
* le rouge uniquement pour les erreurs et les opérations destructives ;
* des gris pour la majorité des éléments de l’interface.

L’utilisateur identifie instantanément la nature de chaque message.

⸻

Checklist du chapitre

Avant de valider une palette :

* ☐ Une couleur primaire unique est définie.
* ☐ Les couleurs secondaires restent discrètes.
* ☐ Les couleurs d’état sont cohérentes.
* ☐ Les textes présentent un contraste suffisant avec leur fond.
* ☐ Les couleurs ne sont jamais le seul moyen de transmettre une information.
* ☐ Les fonds restent sobres.
* ☐ Les boutons principaux sont facilement identifiables.
* ☐ Les éléments similaires utilisent toujours les mêmes couleurs.
* ☐ Les palettes comportent plusieurs nuances pour chaque couleur.
* ☐ L’ensemble de l’interface conserve une identité visuelle cohérente.

⸻

Ce qu’il faut retenir

Une palette de couleurs réussie est presque invisible.

L’utilisateur ne remarque pas les couleurs elles-mêmes : il comprend instinctivement leur signification.

Les couleurs doivent servir le contenu, guider les actions et renforcer la compréhension, jamais détourner l’attention.

⸻

Notes d’application

Pour transformer ces principes en un véritable Design System, le prochain chapitre sera consacré à la typographie. Nous définirons une échelle complète (titres, sous-titres, texte courant, légendes), les espacements verticaux, les longueurs de ligne, les hauteurs de ligne et les règles de lisibilité afin que le texte devienne le principal vecteur de la hiérarchie visuelle. Ce chapitre s’appuiera notamment sur les recommandations de Font Recommendations et les principes de Refactoring UI.
