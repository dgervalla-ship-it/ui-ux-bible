Chapitre 28 — Les Anti-Patterns UX/UI

Les meilleurs designers ne savent pas seulement quoi faire. Ils savent surtout quoi ne jamais faire.

⸻

Objectif

Les anti-patterns sont des erreurs de conception qui reviennent constamment.

Certaines semblent anodines.

Pourtant, elles :

* diminuent la compréhension ;
* ralentissent les utilisateurs ;
* réduisent la confiance ;
* augmentent les abandons ;
* coûtent de l’argent.

Ce chapitre rassemble les erreurs les plus fréquentes observées dans les produits numériques.

⸻

Les Dark Patterns

Les dark patterns sont des interfaces conçues pour manipuler les utilisateurs plutôt que pour les aider.

Ils peuvent améliorer certains indicateurs à court terme, mais dégradent souvent la confiance, la satisfaction et la fidélité.

Exemples à éviter :

* Cases pré-cochées pour des options payantes.
* Désabonnement volontairement compliqué.
* Bouton « Refuser » difficile à trouver.
* Messages culpabilisants (« Non merci, je préfère rester moins productif. »).
* Frais cachés révélés au dernier moment.

Une interface de qualité est transparente et respecte le choix de l’utilisateur.

Cas pratique

Une boutique en ligne affiche :

* une popup d’inscription dès l’ouverture ;
* trois promotions concurrentes ;
* un compte à rebours non authentique ;
* un formulaire de commande de douze champs ;
* un bouton « Continuer » peu explicite.

Résultat :

Les utilisateurs hésitent, quittent la page ou abandonnent leur panier.

Après simplification :

* une seule offre principale ;
* un CTA « Finaliser la commande » ;
* un formulaire réduit aux informations essentielles ;
* des informations transparentes sur les frais et les délais.

Le parcours devient plus clair et plus fiable.

⸻

Checklist du chapitre

Avant de mettre une interface en production :

* ☐ Les menus sont simples et stables.
* ☐ Une seule action principale est mise en avant.
* ☐ Les formulaires sont réduits au nécessaire.
* ☐ Les boutons décrivent clairement leur action.
* ☐ Les contrastes sont suffisants.
* ☐ Les composants possèdent des états de feedback.
* ☐ Les performances sont satisfaisantes.
* ☐ Les parcours sont accessibles au clavier.
* ☐ Les informations importantes ne reposent jamais uniquement sur la couleur.
* ☐ Aucune pratique manipulatrice n’est utilisée.

⸻

Ce qu’il faut retenir

Les anti-patterns ne sont pas seulement des erreurs esthétiques.

Ils créent des frictions qui se traduisent par :

* davantage d’erreurs ;
* davantage d’abandons ;
* davantage de demandes au support ;
* moins de confiance.

Les éviter est souvent plus efficace que d’ajouter de nouvelles fonctionnalités.
