<a id="section-1"></a>
## 1. L’utilisateur ne doit jamais réfléchir

La meilleure interface est celle qui paraît évidente.

Chaque seconde passée à réfléchir est une seconde perdue.

Règle

* Les actions doivent être évidentes.
* Les intitulés doivent être explicites.
* Les icônes ambiguës sont interdites.
* Une personne découvrant le produit doit comprendre son fonctionnement en quelques secondes.
<a id="section-2"></a>
## 2. Une page doit avoir un seul objectif

Chaque écran répond à une question unique.

Mauvais exemple :

* vendre
* expliquer
* rassurer
* recruter
* présenter

sur la même page.

Bon exemple :

Une seule action importante.
<a id="section-3"></a>
## 3. La hiérarchie est plus importante que les couleurs

Avant de choisir une couleur :

* taille
* position
* contraste
* espacement

doivent déjà permettre de comprendre la page.

La couleur vient seulement renforcer cette hiérarchie.
<a id="section-4"></a>
## 4. Les éléments identiques doivent toujours se ressembler

Même bouton.

Même couleur.

Même comportement.

Même animation.

Même état.

La cohérence réduit énormément la charge cognitive.
<a id="section-5"></a>
## 5. Les espaces créent la structure

Ne jamais utiliser des traits lorsque des espaces suffisent.

Le vide est un outil de design.

Une bonne interface contient souvent plus de blanc que de contenu.
<a id="section-6"></a>
## 6. Les utilisateurs scannent

Ils ne lisent presque jamais.

Ils recherchent :

* un titre
* un bouton
* une image
* un prix
* un mot-clé

Il faut donc :

* des titres courts
* des paragraphes courts
* des listes
* une forte hiérarchie visuelle
<a id="section-7"></a>
## 7. Tout élément doit avoir une raison d’exister

Si un élément n’aide pas l’utilisateur :

on le supprime.
<a id="section-8"></a>
## 8. Les actions importantes doivent être visibles immédiatement

Le CTA principal doit être identifiable en moins d’une seconde.
<a id="section-9"></a>
## 9. Les erreurs doivent être impossibles ou faciles à corriger

Prévenir vaut mieux que corriger.

Exemples :

* validation en temps réel
* confirmation des actions destructrices
* possibilité d’annuler
<a id="section-10"></a>
## 10. Donner un retour à chaque action

Chaque interaction doit produire une réponse :

* animation
* changement d’état
* chargement
* succès
* erreur

L’utilisateur ne doit jamais se demander si le système fonctionne.
<a id="section-11"></a>
## 11. La simplicité est une conséquence du travail

Une interface simple est souvent le résultat d’un gros travail de conception.

Supprimer est souvent plus difficile qu’ajouter.
<a id="section-12"></a>
## 12. Réduire le nombre de décisions

Chaque décision fatigue.

Limiter :

* les choix
* les menus
* les options
* les paramètres
<a id="section-13"></a>
## 13. Les utilisateurs préfèrent reconnaître que mémoriser

Ils ne veulent pas retenir.

Ils veulent reconnaître.

Privilégier :

* menus visibles
* suggestions
* historique
* recherche
<a id="section-14"></a>
## 14. Les conventions sont vos alliées

Ne pas réinventer :

* menu
* panier
* profil
* recherche
* fermeture
* retour

Les utilisateurs connaissent déjà ces modèles.
<a id="section-15"></a>
## 15. Les couleurs transmettent une information

Ne jamais utiliser une couleur uniquement pour “faire joli”.

Chaque couleur possède une signification.
<a id="section-16"></a>
## 16. Le contraste est plus important que la saturation

Un bon contraste améliore :

* la lisibilité
* l’accessibilité
* la vitesse de lecture
<a id="section-17"></a>
## 17. Les informations les plus importantes doivent apparaître en premier

Ordre conseillé :
1. titre
2. valeur
3. bénéfice
4. preuve
5. action
<a id="section-18"></a>
## 18. Une bonne interface guide naturellement le regard

Le parcours visuel doit être intentionnel.

On évite que l’utilisateur cherche où regarder.
<a id="section-19"></a>
## 19. Les composants doivent être réutilisables

Créer un bouton une seule fois.

Créer une carte une seule fois.

Créer un champ de formulaire une seule fois.

Le design system garantit la cohérence.
<a id="section-20"></a>
## 20. Les états sont aussi importants que les composants

Chaque composant possède :

* normal
* hover
* focus
* actif
* désactivé
* chargement
* succès
* erreur
<a id="section-21"></a>
## 21. Le contenu est une partie du design

Un bon design avec un mauvais texte reste une mauvaise expérience.
<a id="section-22"></a>
## 22. Les interfaces doivent inspirer confiance

Éviter :

* popups agressifs
* faux comptes à rebours
* CTA trompeurs
* dark patterns

La confiance améliore la conversion à long terme.
<a id="section-23"></a>
## 23. Les performances font partie de l’UX

Une interface lente est une mauvaise interface.

Le ressenti est aussi important que la vitesse réelle.
<a id="section-24"></a>
## 24. L’accessibilité n’est pas optionnelle

Chaque interface doit pouvoir être utilisée :

* au clavier
* avec un lecteur d’écran
* avec un contraste suffisant
* par des personnes ayant des déficiences visuelles ou motrices
<a id="section-25"></a>
## 25. Toujours concevoir pour l’utilisateur, jamais pour le designer

Le but n’est pas de montrer que l’interface est originale.

Le but est que l’utilisateur accomplisse sa tâche le plus rapidement, facilement et sereinement possible.

<a id="section-26"></a>
## Ce qu’il faut retenir

- Rendre la tâche évidente sans supprimer le contexte nécessaire.
- Utiliser la hiérarchie, l’espace et le contenu avant les effets décoratifs.
- Concevoir les états, les erreurs, l’accessibilité et la performance dès le départ.
