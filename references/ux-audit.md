## Objectif
Un audit UX/UI permet d’évaluer une interface de manière objective afin d’identifier :

* les problèmes d’utilisabilité ;
* les incohérences visuelles ;
* les obstacles à la conversion ;
* les problèmes d’accessibilité ;
* les défauts de performance ;
* les opportunités d’amélioration.

L’objectif n’est pas de critiquer une interface.

L’objectif est de l’améliorer.

Quand réaliser un audit ?

Un audit est recommandé :

* avant une refonte ;
* après une mise en production ;
* avant un lancement important ;
* lorsqu’un taux de conversion baisse ;
* lorsqu’un support utilisateur reçoit beaucoup de questions ;
* régulièrement, même sans problème apparent.

## 8. Qualité technique
Chaque dimension est évaluée séparément.

La méthode d’audit

Chaque critère reçoit une note.

Note	Signification
0	Non conforme
1	Très insuffisant
2	À améliorer
3	Correct
4	Bon
5	Excellent

Cette méthode permet de comparer plusieurs interfaces et de suivre leur progression dans le temps.

Partie 1 — Architecture

Navigation

* ☐ Les utilisateurs savent où ils se trouvent.
* ☐ La navigation est cohérente.
* ☐ Les intitulés sont compréhensibles.
* ☐ Les catégories sont logiques.
* ☐ Les pages sont faciles à retrouver.
* ☐ Les actions principales sont accessibles rapidement.
* ☐ Le fil d’Ariane est présent lorsque nécessaire.
* ☐ Les menus ne sont pas surchargés.
* ☐ Les filtres sont faciles à comprendre.
* ☐ La recherche est disponible lorsque nécessaire.

Partie 2 — Hiérarchie visuelle

* ☐ Une action principale domine chaque écran.
* ☐ Les titres sont clairement identifiables.
* ☐ Les contrastes sont suffisants.
* ☐ Les espacements sont réguliers.
* ☐ Les couleurs suivent une logique.
* ☐ Les composants similaires ont le même style.
* ☐ Les éléments importants apparaissent avant les détails.
* ☐ Le regard suit un parcours naturel.

Partie 3 — Typographie

* ☐ Une seule famille de police est utilisée.
* ☐ L’échelle typographique est cohérente.
* ☐ Les lignes sont confortables à lire.
* ☐ Les paragraphes sont courts.
* ☐ Les textes secondaires sont clairement différenciés.
* ☐ Les titres suivent une hiérarchie logique.

Partie 4 — Couleurs

* ☐ Une palette cohérente est utilisée.
* ☐ Les couleurs ont une signification stable.
* ☐ Les contrastes sont suffisants.
* ☐ Les états (succès, erreur, avertissement) sont cohérents.
* ☐ Les couleurs ne sont jamais le seul indicateur d’information.

Partie 5 — Composants

* ☐ Les boutons sont cohérents.
* ☐ Les formulaires utilisent les mêmes règles.
* ☐ Les cartes possèdent une structure identique.
* ☐ Les tableaux respectent les mêmes conventions.
* ☐ Les modales suivent un comportement uniforme.
* ☐ Les composants possèdent leurs états (hover, focus, disabled, loading).

Partie 6 — Formulaires

* ☐ Les champs sont regroupés logiquement.
* ☐ Les labels sont visibles.
* ☐ Les messages d’aide sont utiles.
* ☐ Les erreurs expliquent comment corriger le problème.
* ☐ La validation intervient au bon moment.
* ☐ Les formulaires sont utilisables au clavier.

Partie 7 — Accessibilité

* ☐ Les contrastes sont conformes.
* ☐ Les images informatives possèdent un texte alternatif.
* ☐ Les boutons sont accessibles au clavier.
* ☐ Le focus est visible.
* ☐ Les liens sont explicites.
* ☐ Les zones tactiles sont suffisamment grandes.
* ☐ Les animations peuvent être réduites.

Partie 8 — Responsive

* ☐ L’interface fonctionne sur mobile.
* ☐ Les contenus restent lisibles.
* ☐ Les tableaux s’adaptent correctement.
* ☐ Les menus restent accessibles.
* ☐ Les formulaires restent faciles à remplir.

Partie 9 — Performance

* ☐ Les pages se chargent rapidement.
* ☐ Les images sont optimisées.
* ☐ Les polices sont optimisées.
* ☐ Les animations restent fluides.
* ☐ Les états de chargement sont prévus.

Partie 10 — Conversion

* ☐ L’objectif principal est clair.
* ☐ Les CTA sont visibles.
* ☐ Les bénéfices sont compréhensibles.
* ☐ Les preuves sociales sont présentes lorsque pertinentes.
* ☐ Les formulaires demandent peu d’informations.
* ☐ Les éléments de confiance sont visibles.

Identifier les problèmes

Tous les problèmes n’ont pas le même impact.

Classe-les selon leur gravité.

Niveau 1 — Critique

Empêche l’utilisateur de terminer sa tâche.

Exemples :

* paiement impossible ;
* formulaire inutilisable ;
* navigation bloquante.

À corriger immédiatement.

Niveau 2 — Important

Ralentit ou perturbe l’utilisateur.

Exemples :

* CTA peu visible ;
* hiérarchie confuse ;
* messages d’erreur incomplets.

À corriger rapidement.

Niveau 3 — Mineur

N’empêche pas l’utilisation mais dégrade la qualité perçue.

Exemples :

* espacements irréguliers ;
* incohérences de style ;
* alignements imparfaits.

Prioriser les améliorations

Toutes les améliorations n’ont pas le même retour sur investissement.

Utilise une matrice simple :

Impact	Effort	Priorité
Fort	Faible	Très haute
Fort	Fort	Haute
Faible	Faible	Moyenne
Faible	Fort	Basse

Commence toujours par les améliorations ayant un fort impact pour un faible effort.

Documenter les résultats

Un rapport d’audit doit contenir :

* le problème observé ;
* son impact sur l’utilisateur ;
* des captures d’écran si nécessaire ;
* une recommandation claire ;
* un niveau de priorité.

L’objectif est que l’équipe puisse agir sans ambiguïté.


<a id="section-10"></a>
## Cas pratique
Imaginons une plateforme SaaS.

L’audit révèle :

* le bouton principal est peu visible ;
* le formulaire d’inscription demande 12 informations ;
* les contrastes sont insuffisants sur les textes secondaires ;
* le menu change selon les sections.

Après correction :

* le formulaire est réduit à 3 champs ;
* le CTA est mis en évidence ;
* les contrastes sont améliorés ;
* la navigation est unifiée.

Le résultat est une interface plus simple, plus accessible et plus efficace.

Checklist finale d’audit

Avant de considérer une interface comme prête :

* ☐ L’objectif principal est identifiable en moins de 5 secondes.
* ☐ Les utilisateurs savent toujours où ils sont.
* ☐ Les composants sont cohérents.
* ☐ Les textes sont clairs.
* ☐ Les formulaires sont simples.
* ☐ Les erreurs sont explicites.
* ☐ Les contrastes sont conformes.
* ☐ Les performances sont satisfaisantes.
* ☐ L’expérience mobile est complète.
* ☐ Les décisions de design sont documentées.

Ce qu’il faut retenir

Une bonne interface n’est jamais terminée.

Elle est observée, mesurée, testée et améliorée en continu.

Un audit UX/UI transforme des impressions subjectives en constats objectifs et permet de prioriser les évolutions qui auront le plus d’impact sur les utilisateurs et sur les objectifs du produit.
